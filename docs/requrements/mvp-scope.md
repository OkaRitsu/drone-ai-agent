# MVP範囲
## MVP定義
### 目的
ユーザがAIアプリを経由してドローンを操作し、以下の仮説を検証する：
* AIアプリだけでドローン操縦を完結できるか
* AIエージェントがユーザの意図したタスクを完了できるか
* AIエージェントがドローンを操縦するために必要な機能をTELLOが有しているか
### 対象ユーザ
* ドローン操縦の経験があまりない人（ドローンでやりたいことのイメージはある）
* ドローン1台（TELLO）
### 成功の定義
* ユーザが思い描いているタスクをテキスト情報のみで完了する
* ドローンが墜落することなく着陸する
* AIエージェントでドローンを活用するために必要なドローンの要素が明確になる
## スコープ
### MVP煮含める
| 機能 | 理由 |
|--------|------|
| AIアプリを通じたドローンの状態取得 | AIアプリがドローンの状態を把握せずに操作させるのは危険 |
| AIエージェントがドローン映像を活用 | 映像のあり・なしで可能なタスクが大きく変わる |
| ダッシュボードによる状態モニタリング | AIエージェントのみだとユーザ側の不確実性が増加する |
| AIエージェントによるドローンの操作 | コア体験の中心 |
| 飛行レポート作成 | 飛行後の課題を示せるようにする |
### MVP煮含めない
| 機能 | 理由 |
|--------|------|
| 補助機能の活用 | SLAMや画像認識を使った高度なタスクは将来 |
| 飛行ログを用いた正確な飛行レポート | 実際の飛行ログを活用するための情報量などは別途検証 |
## タイムライン（目安）
| フェーズ | 期間 | 内容 |
| --- | --- | --- |
| MVP開発 | 1か月 | コア機能の実装 |
| AIアプリ検証 | 1週間 | 利用AIモデルの検証 |
| ユーザテスト | 2週間 | 実際に利用してもらい課題を整理 |
| Phase 2 | 2か月 | 課題を基に機能を拡充 |
| Pahse 3 | - | AIエージェントと連携するためのドローンを開発 |
## 制約条件
* TELLO を使用する
* AIエージェントの互換性を考慮しMCPサーバを構築する
* ユーザがリアルタイムでドローンの状況を確認できるようにする
## リスクと対策
| リスク | 対策 |
| --- | --- |
| AIエージェントの不確実性 | MCPサーバ側でフェールセーフを実現し、AIエージェントが危険の操作を実行することを防ぐ |
| AIアプリの接続不能 | 飛行中の外部AIサービスの障害やアクセス制限によりAIアプリを利用できなくなった場合に直接操作できるようにしておく |
